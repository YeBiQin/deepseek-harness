# 插件开发学习路线

这组教程把 DeepSeek Harness 的开发入门拆成四个可运行的练习：先加载插件，再注册工具，然后让插件接受配置，最后把插件打包并安装到 profile。

## 适用范围

教程针对已经完成仓库安装、能够在源码仓库根目录运行 `pnpm dsh web` 的读者。示例使用仓库中的 [`scratch-plugin`](../../../scratch-plugin)，所有命令都应从仓库根目录执行。

教程只覆盖开发入门。插件生命周期、Service、Event、Effect 的完整语义见[模块二](../module-2-plugin-lifecycle.md)；工具的完整执行约定、策略钩子和 UI 展示见[模块五](../module-5-capability-and-tools.md)和[工具编写参考](../../../docs/cookbook/adding-a-tool.zh.md)。

## 学习顺序

| 篇目 | 主题 | 可观察结果 |
|---|---|---|
| [第 1 篇：第一个插件](01-first-plugin.md) | `apply(ctx)`、Overlay、`inject`、Effect 和插件形态 | Web 启动时看到插件加载日志 |
| [第 2 篇：开发一个工具](02-build-a-tool.md) | `defineTool`、参数校验、规范值和模型可见结果 | 模型调用 `greet` 并得到结果 |
| [第 3 篇：插件配置](03-plugin-config.md) | `Config` schema、默认值和加载期校验 | 在 `cordis.yml` 中修改问候语 |
| [第 4 篇：打包与安装插件](04-package-install.md) | Bundle、profile、安装和 Patch 层顺序 | 用 `dsh plugin` 安装自己的组合包 |

每一篇都给出代码路径、运行命令和验证结果。执行结果与文档不一致时，以当前源码、类型、测试和 `docs/` 中的权威文档为准，并记录实际差异。

## 教程写作约定

- 每个章节先提出一个明确问题，再给出概念、操作和验证，不为了套模板添加无关步骤。
- 原理性结论链接到仓库中的权威文档或源码；无法直接验证的内容标注为“推断”。
- 示例必须使用真实入口和真实路径，说明保存位置、运行方式和预期结果；伪代码不作为验证依据。
- 面向初学者使用白话解释，但类比只用于建立直觉，不能替代类型、实现和测试。
- 只保留当前工程需要的规则、限制、失败语义和清理责任；个人机器差异、历史过程和重复说明不写入教程。

### 教程结构

每篇教程至少说明目标、前置条件、配套工程、操作步骤、可观察验证、术语和参考资料。概念主题按“问题 → 概念 → 示例 → 原理”展开；操作主题按“目标 → 命令 → 预期结果 → 关键点”展开；对比主题先给总表，再解释选择逻辑。

教程不为了凑齐固定章节而添加空洞的“常见错误”或“动手练习”。只有当某个练习能验证当前主题的真实行为时，才保留它。

### 交付检查

- 事实能由源码、类型、测试或仓库文档验证；推断要明确标记。
- 示例使用真实入口、真实路径和可运行代码，不使用看起来正确的伪代码。
- 同一术语在全文保持一致，第一次出现时给出足够解释。
- 类比只帮助建立直觉，并注明它不能替代实现契约。
- 删除历史叙述、个人环境特例、重复目录清单和无法观察的完成状态。
